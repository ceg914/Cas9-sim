# 테스트 계획과 결과 (v0.1.0)

## 돌리는 방법

```bash
dotnet test tests/PaleoSphere.Tests.csproj              # 자동 테스트 158개
godot --headless --path . -- --selftest                  # 엔진 안 통합 점검
godot --path . --resolution 1600x900 -- --uitest         # UI 통합 점검(창 필요)
tools/check.sh --with-ui                                 # 위 전부
```

내보낸 실행 파일에서도 `PaleoSphere.console.exe --headless -- --selftest`, `-- --uitest`가 같은 점검을 합니다.

## 필수 시나리오

| 시나리오 | 상태 | 결과 |
|---|---|---|
| 풍부한 초원 | ✅ | `lush_lowland`: 30마리가 20일 동안 먹고 마시고 쉬며 전원 생존(자동 테스트). 120일 실행에서도 전원 생존, 식생 70 t 안팎 유지 |
| 자원 부족 | ✅ | `scarce_resources`: 45일 안에 아사 발생(자동 테스트). 120일 실행에서 30마리 중 6마리 생존 |

| 가뭄 | ⬜ | 날씨 미구현. 물이 전혀 없는 세계에서 전원 탈수하는 것만 확인 |
| 세대교체 | ⬜ | 번식 미구현 |
| 극한 부하 | 🟡 | 5000마리 한도, 생성·삭제·저장·불러오기 반복은 자동 테스트. 화면 부하는 미측정 |

과밀(512 m 세계에 120마리)에서는 식생이 76 t → 27 t로 줄고 개체수가 25마리 안팎으로 떨어진 뒤 식생이 회복됩니다.

## 엔진 안 점검

**셀프테스트(9항목):** 정의 데이터 읽기(PCK 안의 JSON 포함), 세계 생성·배치, 3000틱 재현성, 섭식으로 식생 감소, 세이브 쓰기·읽기, 불러온 상태 일치, 불러온 뒤 1000틱 일치, 손상 세이브 거부.

**UI 통합 점검(11항목):** 실제 마우스·키 이벤트를 넣어 확인합니다. 클릭으로 개체 선택, 상세 정보 조회, F 추적, Space 재생, 배치 도구 클릭(30 → 40마리), 교란 도구 클릭 후 도주, Esc로 도구 끄기, 저장, 삭제, 불러오기 후 상태 복원, 불러온 뒤 일시정지.

## 사람이 직접 확인해야 하는 것

자동 점검이 닿지 않는 부분입니다. Windows에서 실행해 확인이 필요합니다.

1. `PaleoSphere.exe`가 뜨고 한글이 제대로 보이는가.
2. WASD 이동, 우클릭 드래그 회전, 휠 줌이 자연스러운가.
3. `새 세계` 창에서 값을 바꿔 만들기, `저장`·`불러오기` 창의 목록·삭제 버튼, `설정`의 언어·배율 변경.
4. 창 크기를 줄였을 때 패널이 잘리거나 겹치지 않는가(최소 1180×700).
5. 개체 100마리에서의 FPS(`성능 분석` 탭).
6. 한 시간 이상 켜 두었을 때 메모리와 프레임 시간.

# PALEOSPHERE — 선사 생태계 시뮬레이터

> Windows 3D 생태계 시뮬레이터 · 초대형 프로젝트 개발 기획서  
> 문서 버전: 1.0 · 작성일: 2026-11-16 · 목적: Claude Code 구현 지시 및 인수 기준

## 0. 프로젝트 정의

**목표:** 사용자가 지형과 생물군을 설계하면, 선사 생물이 스스로 탐색·섭식·휴식·도주·사회적 상호작용·번식·사망하고 식생·수자원·기후와 영향을 주고받는 3D 생태계 시뮬레이터를 제작한다.

**제품 형태:** Windows 10/11 x64, 오프라인 우선, 단독 실행 가능한 EXE 및 리소스 디렉터리. 게임보다 **관찰·실험·생태계 설계**에 비중을 둔다.

**핵심 원칙**
1. 생태 시뮬레이션 상태와 3D 시각화를 분리한다. 렌더링 프레임률이 달라도 결과가 바뀌지 않아야 한다.
2. 화석으로 확인된 내용, 학술적 가설, 게임적 단순화를 UI와 데이터에 구분하여 표시한다.
3. 동일한 시드·설정·버전에서 가능한 한 동일한 시뮬레이션 결과를 재현한다.
4. 최종 기능은 모듈화하고 작은 수직 슬라이스부터 개발한다.
5. 3D 모델·애니메이션·음향의 라이선스를 기록하고 무단 배포하지 않는다.

**비목표(초기 버전):** 분자 수준 DNA 모델, 고정밀 CFD, 실제 고생물 행동의 과학적 재현, 자동 생성된 3D 공룡 모델의 품질 보장, 멀티플레이어, 거대한 행성 규모 월드.

## 4. 내부 아키텍처

### 4.1 계층 원칙

```text
입력·UI → 명령(Command) → 시뮬레이션 코어 → 읽기 전용 스냅샷 → 3D 렌더러·UI
                                  │
                                  ├→ 이벤트 로그·통계
                                  └→ 저장/실험 재현
```

- **Simulation Core:** Godot 노드에 의존하지 않는 순수 C# 중심. 테스트는 화면 없이 실행 가능해야 한다.
- **World State:** 개체, 자원, 환경, 시간의 단일 권위 상태.
- **Presentation:** 상태 스냅샷을 보간해 표시. 렌더링 프레임마다 게임 규칙을 계산하지 않는다.
- **Command Bus:** 개체 배치·삭제, 지형 수정, 환경 변경을 검증한 명령으로 처리.
- **Event Bus:** 출생·사망·포식·기후 변화 등의 사건 발행.
- **Telemetry:** 틱별 비용, 개체 AI 계산 비용, 프레임 타임 계측.

### 4.2 고정 틱과 업데이트 빈도

- 논리 시간은 고정 간격 `simulation_tick`으로 처리한다. 기본값은 구현 과정에서 실측으로 결정한다.
- 개체 생리 상태 갱신은 일정 틱마다, 의사결정·경로 탐색은 더 낮은 빈도로 실행한다.
- 식생·토양·기후는 필요에 따라 느린 틱으로 계산한다.
- 렌더러는 이전/다음 상태를 보간해 부드럽게 그린다.
- 10x 배속은 실제로 계산 가능한 틱 처리량을 초과하지 않도록 제한하고 UI에 실효 배속을 표시한다.
- **결정론:** 고정 시드 난수, 고정 순서의 이벤트 처리, 안정적인 ID를 사용한다. 멀티스레딩 시 비결정적 갱신 순서에 유의한다.

### 4.3 개체 상태 데이터(개념 스키마)

```json
{
  "id": 10001,
  "species_id": "species_example_herbivore",
  "position": [120.0, 8.0, 340.0],
  "age_days": 1200,
  "sex": "unknown",
  "health": 0.92,
  "energy": 0.64,
  "hydration": 0.71,
  "stress": 0.12,
  "life_stage": "adult",
  "behavior": "forage",
  "target_entity_id": null,
  "traits": {
    "body_size": 1.04,
    "metabolism": 0.97,
    "speed": 1.02
  },
  "parents": [null, null],
  "rng_stream_id": 10001
}
```

위 수치는 **예시 데이터**이며 실제 공룡의 생리·행동을 의미하지 않는다. `sex` 등 미확정 요소는 `unknown`을 허용한다.

### 4.4 AI 구조

**기본:** Utility AI(행동별 점수 계산) + 상태 머신(행동 실행). 고급 행동에만 행동 트리 사용.

각 행동은 전제 조건과 점수 계산식을 갖는다. 예시 후보는 `Drink`, `Forage`, `Rest`, `Flee`, `FollowHerd`, `Explore`, `Reproduce`이다. **개체별 행동 선정 근거를 디버그 패널에서 추적 가능**하게 한다. 생존에 필요한 필수 조건은 별도의 안전 규칙으로 처리한다.

**경로 탐색:** 공간을 큰 구역으로 나눠 상위 경로를 찾고, 근거리에서는 로컬 회피를 사용한다. 모든 개체가 매 프레임 전체 경로를 재탐색하지 않도록 큐·재계산 간격·캐시를 둔다.

**LOD:** 근거리의 개체는 전체 AI + 상세 애니메이션, 중거리는 낮은 빈도 AI + 간소화 렌더링, 원거리는 집단 수준 또는 저빈도 개체 시뮬레이션으로 관리한다. 단, 같은 시드에서 LOD에 따른 결과 차이는 실험·검증한다.

### 4.5 생태·유전 모델

- 식물의 위치별 바이오매스가 실제로 감소·성장하도록 모델링한다.
- 초식동물의 섭식은 자원을 소비하고 에너지 상태를 높이며, 먹이 부족은 생존·번식에 영향을 준다.
- 포식은 추적, 접근, 성공/실패 판정의 **게임적 추상 모델**로 구현한다.
- 사체·배설·낙엽 등은 선택적으로 자원 환원에 포함한다.
- 형질은 초기에는 정규화된 연속 값으로 표현하고, 상속·변이 규칙을 문서화한다.
- 개체군의 변화를 '진화가 일어났다'고 단정하지 않고, 형질 분포·세대 변화와 모델 가정으로 보고한다.
- 종의 공존은 시대·지역이 겹치는 과학적 시나리오와, 사용자가 자유롭게 섞는 샌드박스 시나리오를 분리한다.

## 5. 3D 아트 및 렌더링 설계

### 5.1 시각적 방향

사실적인 자연환경을 목표로 하되, **정확하지 않은 고생물 외형을 확정된 사실처럼 제시하지 않는다.** 종별로 외형 가정과 참고 자료를 연결한다.

- 지형: 높이맵, 지형별 재질 블렌딩, 수계, 안개, 그림자.
- 식생: 풀·관목은 인스턴싱, 나무는 거리별 모델·임포스터 적용.
- 생물: 종별 리깅된 3D 모델, 걷기·달리기·섭식·휴식·위협 반응.
- 애니메이션: AnimationTree 블렌딩, 이동 속도에 따른 모션 동기화.
- 개체 표시: 근거리 3D, 중거리 저폴리곤, 원거리 임포스터/아이콘.
- 디버그 보기: 이동 경로, 탐지 범위, 자원 맵, AI 목표 위치 표시.

### 5.2 자산 파이프라인

1. 임시 도형·캡슐 메시로 **전체 게임플레이를 먼저 완성**한다.
2. 이후 확실한 사용 권리가 있는 리깅 모델을 종별로 교체한다.
3. 모델마다 좌표계, 스케일, 원점, 애니메이션 이름, 충돌체 규격을 통일한다.
4. 라이선스·원본 링크·제작자·수정 여부를 `LICENSES.md`와 자산 메타데이터에 기록한다.
5. 최소 1종의 고품질 모델과 1종의 초식동물 모델로 최종 표현 파이프라인을 검증한다.

## 11. Claude Code 개발 실행 지침

아래 프롬프트를 Claude Code에 전달한다. 실제 구현 과정에서 프로젝트 구조와 단계별 산출물의 완료 상태를 명확히 기록한다.

### 구현용 마스터 프롬프트
